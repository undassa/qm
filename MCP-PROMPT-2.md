# Дополнение к промпту про слой сущностей и MCP

Отправлять после `MCP-PROMPT.md`, не вместо него. Составлено 2026-09-07; числа замерены.

---

Это дополнение к заданию из `MCP-PROMPT.md`. Оно **отменяет один абзац** того промпта и
добавляет две вещи, которых там не было. Всё остальное в силе.

## Отмена: про шесть видов без проекции

В первом промпте сказано: «по ним отвечай отказом с именем, а не пустым списком».
**Так делать не надо.** Довод был построен на защите агента от пустого ответа, и он подменял
собой настоящее решение.

Набор строится **полным**. Поэтому «документа нет» — это утверждение о наборе, и место ему в
плане документов, а не в поведении инструмента. План уже так и устроен: из 29 позиций 25
есть, 3 объявлены отсутствующими, и у каждой написана причина — «нет: писать нечего до
первых прогонов», «нет: нужны к первому выпуску». Это лежит в `project_document_plan`,
колонка `claim` (`present` · `absent` · `self`).

Различай три состояния, и не путай их:

| Состояние | Как узнаётся | Что значит |
|---|---|---|
| объявлено и есть | план говорит «есть», сущность отвечает | работаем |
| объявлено, нет, причина написана | план говорит «нет: …» | названная работа, она видна |
| не объявлено вовсе | плана не спрашивали | дефект плана, и ловить надо его |

Пустой ответ — правда там, где он правда: отвергнутых решений в наборе ноль, и это факт, а
не пробел. Возвращай пустой список.

**Что из этого строить.** Слой сущностей обязан уметь ответить «положено ли этому быть» —
по плану, а не по наличию. И добавь то, чего план сегодня не объявляет: **положена ли виду
предметная таблица**. Сейчас известно, что `runbook.md` есть; что разбора его процедур нет —
не записано нигде, и отличить «ещё не разложили» от «и не надо» можно только спросив
человека. Объяви это у вида — тогда «сколько видов осталось разложить» станет запросом.

**Шесть видов распадаются, и по-разному.** Три — незакрытая работа: проектные виды (7
документов: крейты, события шины, угрозы, файлы дерева), красные задачи (82, имя `R-M1-T1`
несёт родителя `M1-T1` и перечень проверок), документы после выпуска (4: процедуры, шаги
первого дня, отложенное со ссылками на решения). У трёх «проекция» значит другое:
руководства суть проза; мокапы надо уметь отдать на отображение, а не разложить; у справки
ценность в провенансе — откуда взято и когда.

## Добавление 1: история — это три таблицы, а не одна

Под словом «история» в наборе лежат три вещи с разными ключами и разными потребителями.
Замер:

```
журнал изменений сущности   323 вопроса из 359 ведут таблицу «Дата · Событие · Кем»
версия нормы                3 объявленные версии конституции (2.6 · 2.7 · 2.8)
замер                       81 датированный замер в 35 документах
```

**Событие сущности** — с вещью что-то произошло, и известно кто. Вопрос ведёт это сам
таблицей; у задачи то же выражено закрывающим коммитом, у гейта — переоткрытием.

```sql
CREATE TABLE entity_event (
  project_id text NOT NULL, entity_kind text NOT NULL, entity_id text NOT NULL,
  ord integer NOT NULL,
  at date,                             -- пусто законно: набор пишет «—», когда даты нет
  event text NOT NULL, actor text NOT NULL DEFAULT '',
  by_decision text, by_commit text,
  PRIMARY KEY (project_id, entity_kind, entity_id, ord)
);
```

**Версия нормы** — конституция объявляет номер, и набор его **цитирует**: `ADR-0164` пишет
«версия конституции 2.6 → 2.7». Цитируемое число есть идентификатор, и строка ему положена
по этому признаку. Сегодня эта история физически сидит внутри тела шестнадцатой статьи.

```sql
CREATE TABLE norm_version (
  project_id text NOT NULL, entity_kind text NOT NULL, entity_id text NOT NULL,
  version text NOT NULL, at date NOT NULL,
  changed text NOT NULL, by_decision text,
  PRIMARY KEY (project_id, entity_kind, entity_id, version)
);
```

**Замер** — «чем получено и сколько вышло». У него нет актора, у него есть способ; этим он и
отличается от события.

```sql
CREATE TABLE measurement (
  project_id text NOT NULL, subject text NOT NULL, at date NOT NULL,
  value text NOT NULL, method text NOT NULL,
  stated_in_kind text, stated_in_id text,
  PRIMARY KEY (project_id, subject, at)
);
```

Одной таблицей их не свести: у события есть кто и нет величины, у замера есть величина и
способ, но нет кто, у версии есть номер, на который ссылаются другие документы. Общая форма
стоила бы трёх пустых колонок в каждой строке.

Ревизии документа (`project_document_revisions`, 1690 строк) остаются отдельно: они
механические, про текст, и ничего не знают ни о норме, ни о замере.

**Зачем это агенту.** Замер снимает нужду держать число прозой рядом с предметом: правило
говорит, **чем мерить**, а сколько вышло и когда — отвечает запрос. Сегодня 81 такой замер
вписан внутрь правил, и пять из них уже разошлись с фактом.

## Добавление 2: чего в наборе нет и это надо объявить

Не построить, а **объявить в плане**, чтобы отсутствие стало видимой работой:

**Заморозка версии.** Проверка харнеса ищет её рядом с документом версии и сверяет каждую
строку с набором; у `v1` заморозки нет. Пока версия одна — цена нулевая; на `v2` без неё не
вычислить дельту, а дельта — то, из чего версия берёт этапы.

**Запись о выпуске.** Есть процедура (`70-after/release.md`) и она написана для прежнего
продукта — упоминает репозитории `console/*`, `devops`, `docs / load / meta`. Записи о том,
что выпущено, когда и с какими требованиями, нет вовсе. `CHANGELOG`, форму которого эта же
процедура предписывает, не существует.

**Связь «разрыв пути закрыт требованием».** В `cjm.md` семь разрывов, колонка «Чем
закрываем» — проза: «ведущий по восьми шагам», «приёмка смены». Идентификатора требования
нет ни у одного. Это нельзя вычислить, это можно только завести, и это суждение владельца, а
не работа сервера. Схема пусть держит место; таблица остаётся пустой, пока связь не
записана — пустая честнее заполненной догадками.

## Приёмка дополнения

Четыре прогона, каждый — запуск.

1. `next_task` для `M8-T10` не отдаёт её как готовую: она зависит от этапа `M8` целиком.
2. Запрос «какие виды объявлены, но не разложены» отвечает списком, а не «спроси человека».
3. Запрос «как двигалось покрытие» отвечает по таблице замеров, а не чтением документа.
4. Запрос «что изменила версия конституции 2.7» отвечает строкой, а не телом статьи 16.

И сломай каждую нарочно, прежде чем объявить зелёной.
