# mh

Интерфейс к работе харнеса и сервер, который его кормит.

Проект показывает **корпус** — комплект документов, которым описан проект, — и то,
что из корпуса выводится: вопросы, требования, решения, проверки, доска задач. Не
как редактор: править документы приходят в git, сюда приходят видеть, где работа
разошлась сама с собой.

## Из чего он состоит

| каталог | что это | состояние |
|---|---|---|
| `web/` | интерфейс на React 19 + vite | работает |
| `server-rs/` | сервер на Rust: читает Postgres, отдаёт интерфейсу | рубеж 1 — только документы |
| `legacy-qm/` | всё, что пришло от qm: рантайм на TypeScript, его плагины и проверки | архив |

Наполняет базу отдельная работа — перенос документов из файлов в
`project_documents`. Сервер файловую систему не читает вовсе: чего нет в базе,
того нет.

## Как запустить

```bash
cd web && npm install && npm run build     # интерфейс собирается в web/dist

cd ../server-rs
MH_DB_URL='postgres://…/qm' MH_IDENTITY_SECRET='…' cargo run
# слушает http://127.0.0.1:8200/next/
```

Без `MH_IDENTITY_SECRET` сервер не поднимается: «пока не настроено, пускаем»
превращает недонастроенный сервер в открытый.

Личность приходит заголовком `x-portal-identity` либо печеньем `mh_identity` —
это `base64url(claims).HMAC-SHA256`, и `exp` в нём **в миллисекундах**. Своего
входа у сервера пока нет; как это устроено и почему временно — в
[`server-rs/DESIGN.md`](server-rs/DESIGN.md).
